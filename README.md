# DocFlow 文流 · 智能文档整理（重构版）

本地优先的文档自动整理工具：文件进目录，自动识别、重命名、分类、归档；拿不准的交人工；
台账对账、邮箱收件、目录监控无人值守。**机器处理确定的事，人处理不确定的事。**

本工程是隔壁 `smart-document-organizer` 的重新设计版，功能对齐并增强，安全与体验重点修复；
原版代码零改动，两库可并存（注意别同时占用 8000 端口）。

## 快速开始

```powershell
python -m pip install -r requirements.txt
python -m pytest tests -q        # 120 项测试（端到端识别/预览/自检/对账/归集/付款核对/安全/失效记录/桌面壳）
python run.py                    # 打开 http://127.0.0.1:8000（自动开浏览器）
python run.py --lan              # 局域网共享：自动生成/沿用访问密码并打印
```

前端已构建在 `frontend/dist`，后端单进程托管；开发模式 `cd frontend && npm run dev`（5173，代理 /api）。

## 桌面版（DocFlow.exe，免 Python）

双击 `dist\DocFlow\DocFlow.exe` 即可，单文件目录里自带 Python 运行时、OCR 模型、PyMuPDF 和前端资源，
装完即用、全程离线。

| 事项 | 说明 |
|---|---|
| 数据目录 | `%LOCALAPPDATA%\DocFlow`（数据库/归档/回收站/备份/日志），首次启动自动创建 |
| 界面 | 原生窗口（系统 WebView2）；缺依赖、创建失败或窗口 20 秒没加载完成，自动改用浏览器界面 |
| 重复启动 | 带实例锁，第二次双击会把已有窗口唤到前台，不会起两份服务 |
| 命令行 | `DocFlow.exe` 开窗口；`--serve` / `--no-window` 只跑服务；`--lan` 局域网；`--port 8123` 指定端口 |
| 环境变量 | `DOCFLOW_HOME` 换数据目录、`DOCFLOW_PORT`、`DOCFLOW_HOST`、`DOCFLOW_DEBUG=1` 开 DevTools、`DOCFLOW_SHELL=webview|browser` 强制界面形态 |
| 日志 | `%LOCALAPPDATA%\DocFlow\logs\desktop.log`（窗口/端口/回退）与 `server.log`（服务本体 + OCR/PDF 等库的输出：桌面版没有控制台，stdout 一律接到这里） |

重新打包（源码目录里执行，产物在 `dist\DocFlow\`）：

```powershell
cd frontend; npm ci; npm run build; cd ..
python -m pip install pyinstaller pywebview
python 发布桌面版.bat            # 等价于 python -m PyInstaller packaging/docflow.spec --noconfirm
```

远程桌面 / 无显卡虚拟机上若窗口画不出来，设 `DOCFLOW_WEBVIEW_FLAGS=--disable-gpu` 再启动。

### 发布与更新（分享给别人 / 后续升级）

把桌面版分发给他人、以及后续功能更新如何同步，见 `docs/发布与更新.md`。
一句话流程：改 `backend/config.py` 里的 `VERSION` → 双击 `发布Release.bat` 自动打包并发布到 GitHub Releases，用户从 `releases/latest` 取最新版（数据在 `%LOCALAPPDATA%\DocFlow`，覆盖不丢）。

### 窗口“无响应”了怎么办

原生窗口一旦在 20 秒内没有完成加载，启动器会记下这个事实（数据目录下的 `.window-state`）、
立刻改用浏览器界面，**下次双击直接进浏览器界面**，不会再让你对着一个卡死的窗口。

- 想再试原生窗口：删掉 `.window-state`，或用 `DOCFLOW_SHELL=webview DocFlow.exe` 启动一次。
- 只想稳定用浏览器界面：`DOCFLOW_SHELL=browser`（或 `DocFlow.exe --no-window`）。
- 常见根因是 WebView2 运行时/显卡驱动异常，更新「Microsoft Edge WebView2 运行时」后重试。

### 文件被外部删掉的记录（“删不掉也移不进回收站”）

现在这类记录可以正常处理：移入回收站会成功（回收站里标为「文件已丢失」，恢复按钮置灰，
彻底删除照常），并且和其它回收记录一样从文档库消失。文档库只对**仍在库里**但磁盘文件缺失的记录
显示「文件缺失」标签，设置 → 系统自检的
「记录与磁盘一致性」会列出它们并提供一键清理。

### AI 辅助（可选）

AI 可不配置：纯规则 + OCR + 样例库即可自动归档（权重自动归一化）。
配置在 设置 → AI 与 OCR：填 Base URL（OpenAI 兼容）、模型、API Key，保存后点「测试连接」。

- 测试连接限死输出长度（`max_tokens=64`）并回报真实耗时。带思考过程的推理模型单次常要
  20~90s，若提示接近超时上限，把「超时（秒）」调到 120 以上，或改用非推理模型。
- 超时、连不上、HTTP 报错都给出具体原因（不再是 `timed out`）；连接失败只等几秒即返回。
- 慢超时不再触发重试：`AI_MAX_RETRIES` 只对响应解析失败等瞬时问题生效，避免 3 次叠加等待。

## 识别口径

类型判定看**命中位置**，不只看规则置信度：文件名与正文抬头（前 4 行）命中＝「这份文件是什么」，
按规则置信度满分；正文深处命中＝只是「提到了」别的单据，按 0.55 折算。
合同的付款条款几乎必然写着「开具发票」「乙方提货」，不区分位置的话 0.92 的发票规则会永远压过
0.90 的合同规则，每份合同都被归成发票（真实翻车样本已进回归测试）。

- 分类证据只用**用户上传时的原始文件名**：归档名是上一次识别自己拼出来的，喂回去会让误判自锁。
- 规则给不出分类时按类型名回落到同名叶子分类（发票→财务/发票，提货单→业务/提货单），
  类型只到「合同」时按抬头细分销售/采购/框架/补充协议——归档目录与业务包角色共用同一口径。
- 用户确认过的同模板样例（指纹命中 0.95）优先于通用关键词规则，否则「改对了」学不进去了。
- 规则中心 → 规则模拟会标注每条命中是「标题命中」还是「正文提及」，误判可直接照着一个词调规则。
- 识别错了不用删重传：文档库 → 行菜单 → 重新识别，原地重跑并搬回正确目录（不新增记录）。

## 金额与当事方口径

「金额」只取**含税总额**，绝不取单价：优先认 `合同总金额 / 价税合计 / 结算总金额 / 合计金额 / 总价 / 价款 / 货款`
这类标签后面的数字（标签与数字之间允许夹 `（人民币）`、换行、`¥`）；`不含税总金额`、`税额`、`保证金`、`违约金`、
`单价` 一律按上下文排除，不作为取数依据。合同只写了「799.05 元/湿吨」这种单价时，按 **单价 × 数量** 推导总额，
且只在正文里数量唯一、大于 1 时才乘；取不到唯一数量就宁可不填，不猜。识别出的单价另存为独立字段 `单价`，
方便核对，不再冒充金额（真实教训：一份 799.05 元/吨 × 10000 吨的合同，金额被抽成 799.05，对账全线飘红）。

**分不清我方还是对方** 时去 设置 → 无人值守 → 本公司名称 填上自己的全称
（如 `华山云创供应链科技（山西）有限公司`）。填了之后：文中等于本公司的名字进 `公司名称`，另一方进 `对方单位`，
业务包的我方/对方也随之拆开；本公司名称没在文档里出现时 `公司名称` 宁可留空，不白送一个虚高的字段覆盖率。
没填时按出现顺序取前两个不同公司名。公司名后缀只认 `公司/集团/银行/厂/中心/事务所/研究院/设计院/合作社`，
避免把「山西宏达钢铁有限公司（买方）」切出奇怪尾巴。

- 手工改过的字段优先级最高：重新识别不覆盖你手填的类型/合同号/金额，只清掉规则本轮没再抽到的**陈旧规则值**
  （否则早期误判写错的 `公司名称` 会永远挂在文档上）。

## 文档归集（业务包）

一份业务 = 一个包：同一合同号下的采购合同、销售合同，以及它们各自的发票、结算单、
提货单/入库单，归档时自动归进同一个业务包，包内按「合同锚点」分组并显示必备单据齐备度（3/4）。

- **必备单据可配**：规则中心 → 归集与必备单据，按合同类型配置需要哪些随附单据、至少几份、是否核对金额
  （销售合同→发票/结算单/提货单，采购合同→发票/结算单/入库单）。
- **缺什么补什么**：详情页把缺失角色显示成虚线占位瓦片，点「上传」就地补单 → 识别归档 → 自动入包 → 齐备度当场重算。
- **合同号是唯一口径**：`contract_key`（归一化合同号）上有唯一索引，一个合同号只有一个包；手工包可以「认领」
  合同号，占号的自动包会被并进来；历史竞态留下的分裂包在启动自检时自动合并。
- **合并建议**：方向相反、对方单位相同、金额相对差 ≤5%、签订日期相距 ≤30 天的销售包与采购包会提示成对
  （阈值见设置 → 无人值守 → 文档归集）；合并只搬条目并写操作日志，可先忽略、也能恢复显示。
- **回款/付款视角**：包详情下方「回款情况」块汇总 该收付 / 凭证合计 / 差额，并列出银行回单、收付款凭证；
  钱没收齐的包在列表上直接挂「未收 30万 / 未付 45.2万」标签。缺凭证时给虚线占位瓦片，点「上传」即补即算。
  回款**不进**必备单据清单——缺凭证这件事只由对账里的「未回款/缺凭证」一条负责，避免同一件事报两条。
- 无合同编号的文档不自动入包，只能在归集页手工建包后拖入；设置 → 系统自检新增「文档归集」一致性项。

## 对账口径

台账 Excel 三张表自动识别（合同台账/结算/回款，表头别名可自动探测，回款表的「付款金额 / 到账日期」
这类列名也读得进来）；对归档文档按 **合同编号变体 + (对方单位,金额) 双通道** 匹配，产出九类差异：
缺必备单据 / 缺结算单据 / 未回款·缺凭证 / 收付金额不符 / 凭证与台账不符 / 金额不符 / 文档无台账 / 日期可疑 / 疑似缺章。

## 回款与付款核对

「该收/该付 → 已收/已付 → 差额」与结算核对同级，销售侧口径是应收回款、采购侧是应付付款，
双向共用一套检查（方向只改文案，不改类型名）：

- **该收付**：已结算金额优先，没有结算数就退回合同金额；两者都拿不到就不报回款差异（不凭空造应收）。
- **已收付**：取「档案库凭证合计」与「台账已记回款」里更可信的大值，避免同一笔钱算两次。
- **判定顺序**：一张凭证都没有 → 「未回款/缺凭证」（台账却记了钱，会写明「台账已记回款 · 档案库无凭证」）；
  有凭证 → 先比账证（台账 vs 凭证，不符报「凭证与台账不符」并就此打住），再比差额（「收付金额不符」，
  写明未收/超出多少）。同一合同最多两条回款差异。
- **容差独立**：回款默认 1%（设置 → 置信度与阈值 → 回款/付款容差），结算/发票对合同金额仍按 0.5%，
  因为手续费、尾差、分批到账是常态，拿结算口径卡回款会天天刷屏。
- **闭环**：从差异抽屉上传银行回单/收付款凭证 → 自动识别归档入包 → 复核后按同一算式重算，
  进容差即关闭并留痕，没进就把新的差额、应到金额回写到这条差异上。

**每条差异都带依据**：点「依据」打开抽屉，显示对应业务包、已匹配的文档（就地预览）、还缺哪些单据，
缺的那一项自带上传入口——上传 → 识别归档 → 入包 → 复核，条件满足即自动关闭并留痕
（`由文档 #12《发票_…》自动补齐发票`），不满足则原地写明「仍缺 提货单」。

**没有台账也能查**：数据源选「档案库自对账」时以已归档合同为锚，期望值取合同金额/签订日期，
实际值取包内发票·结算单与银行回单汇总，检查项与台账模式完全一致；默认「自动」= 有台账用台账，没台账走档案库。
金额比对按单据类型分桶取偏差最大的一类，避免发票+结算叠算出假差异；标记已处理/复核后本期统计同步重算。

差异标记跨期结转，支持 CSV/Excel 导出与定时巡检。

## 回收站与文档库

「移入回收站」= 从文档库搬走，不是打个灰色标记：文件移到回收站目录，记录立刻从文档库列表、
搜索、类型下拉、归档目录计数、看板「文档总数」里消失。列表顶部会挂一条提示
「另有 N 份文档已移入回收站，不在文档库显示」，一键 去回收站 或 在这里显示（按状态筛回 recycled）。

- **恢复回到原样**：回收时记下进入前的状态，已归档的恢复后仍是已归档，文件回到原位置、原分类，
  业务包齐备度与对账依据同时算回来（回收一份发票 → 齐备度 3/3 掉到 2/3 并显示「缺发票」，恢复即复原）。
- 老的回收记录没有这个字段（v2.3.3 之前生成的），恢复时退回「待整理」重走一遍识别，不会报错也不会谎称已归档。
- 回收站条目默认保留 30 天后自动清理（设置 → 目录与归档，0 = 永不自动删）；「彻底删除」需显式 confirm，才真正不可逆。
