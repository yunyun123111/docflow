# DocFlow 发布与更新（GitHub Releases）

功能持续更新后，靠 GitHub Releases 把桌面版分发给别人：每个 `vX.Y.Z` 标签对应一个
Release，里面附上整包 `DocFlow-Desktop-vX.Y.Z.zip`（免安装、自带 Python 运行时/OCR/前端）。
用户永远从 `releases/latest` 拿最新版；数据在 `%LOCALAPPDATA%\DocFlow`，覆盖程序目录不丢数据。

## 一次性准备（每台开发机只做一次）

1. 安装并登录 GitHub CLI：
   ```powershell
   winget install GitHub.cli
   gh auth login
   ```
2. 在 GitHub 上建一个仓库（建议 Private 或 Public 均可），然后初始化本地仓库并接上远端：
   ```powershell
   cd docflow
   git init -b main
   git add .
   git commit -m "DocFlow 初始提交"
   git remote add origin https://github.com/<owner>/<repo>.git
   git push -u origin main
   ```
   > `.gitignore` 已排除 `data/`、`.env`、`release/`，不会把文档数据/密码/产物传上去。

## 日常发版（改完代码后）

1. **升版本号**：只改一处 —— `backend/config.py` 里的 `VERSION = 'x.y.z'`。
   发布脚本会自动把它同步进 `packaging/version_info.txt` 和 exe 文件属性，不会再对不上。
   （`app.py` 的 API 版本也已改为引用同一个 `VERSION`。）
2. **双击根目录的 `发布Release.bat`**（或命令行运行脚本）。它会依次：
   读取版本号 → 重生成 `version_info.txt` → 构建前端 → PyInstaller 打包
   → 压出 `release\DocFlow-Desktop-vX.Y.Z.zip` → 创建/更新 GitHub Release 并上传 zip。
3. 成功后打印下载入口：`https://github.com/<owner>/<repo>/releases/latest`，把它发给用户即可。

常用参数：
```powershell
.\packaging\release.ps1                       # 完整发版
.\packaging\release.ps1 -SkipBuild            # 复用现有 frontend/dist（更快）
.\packaging\release.ps1 -DryRun               # 只构建打包，不推 GitHub（本地验证）
.\packaging\release.ps1 -Notes "修复对账" -Prerelease
.\packaging\release.ps1 -Repo owner/name      # git remote 未配置时显式指定仓库
```

## 用户怎么拿到更新

- **桌面版各自安装**：给固定链接 `.../releases/latest`，用户下载新 zip，关掉程序、
  解压覆盖旧目录即可，数据无损。人数少或更新不频繁时这就够了。
- **局域网共用一套（最省心）**：只在主机更新、重启服务，大家刷新浏览器就是新版，客户端零同步。
- **App 内检查更新（可选，后续再做）**：脚本每次都会生成 `release\latest.json`
  （含 `version`/`tag`/`asset`/`sha256`/`size`/`notes`）。将来在 `desktop_app.py` 启动时读
  远端这份 JSON，比对本地 `VERSION`，就能提示“发现新版本，是否更新”，并复用 `sha256` 校验。
  需要的话可以把旧版 `smart-document-organizer\update_tools` 里的下载/校验/回滚逻辑移植过来。

## 说明与坑

- PyInstaller 桌面版是整目录（约 300MB+），更新按**整包替换**，不做单文件增量。
- `gh` 不可用时脚本会尝试 `GITHUB_TOKEN` 走 GitHub API 兜底；两者都没有则只产出 zip 并打印手动上传提示，不影响本地包。
- 版本号务必每次发版前 bump，否则 `releases/latest` 和未来的“是否更新”判断会失真。
- 别和旧版 `smart-document-organizer` 同时占用 8000 端口。
